# Публикация Breast Risk Hub в интернете через Render

После публикации приложение будет открываться по HTTPS-ссылке с любого
компьютера, телефона или планшета. Компьютер разработчика может быть выключен.

## Что понадобится

1. Репозиторий GitHub с файлами проекта.
2. Бесплатная учетная запись Render.
3. Несколько минут на первую сборку.

## Вариант A: через Blueprint

В корне проекта уже находится файл `render.yaml`.

1. Загрузите содержимое этой папки в корень GitHub-репозитория.
   В репозитории рядом должны находиться `Dockerfile`, `render.yaml`,
   `requirements.txt` и папка `app`.
2. Войдите в Render через GitHub.
3. Нажмите **New → Blueprint**.
4. Выберите репозиторий проекта.
5. Render найдет `render.yaml`.
6. Нажмите **Deploy Blueprint**.
7. Дождитесь статуса **Live**.
8. Откройте выданный адрес вида:
   `https://breast-risk-hub-xxxx.onrender.com`.

## Вариант B: Web Service вручную

1. Нажмите **New → Web Service**.
2. Подключите GitHub-репозиторий.
3. Runtime/Language: **Docker**.
4. Region: **Frankfurt**.
5. Instance type: **Free** для пилотной проверки.
6. Health Check Path: `/api/health`.
7. Нажмите **Deploy Web Service**.

Render использует команду из `Dockerfile` и автоматически передает
приложению необходимый порт.

## Ограничение бесплатного тарифа

Бесплатный сервис отключается после периода бездействия. Первый посетитель
после простоя может ждать около минуты, пока приложение запускается.
Для постоянно работающего клинического инструмента позднее следует перейти
на платный always-on instance.

## Собственный адрес

После проверки можно подключить домен, например:

- `breastrisk.ru`;
- `calculator.example.ru`;
- `breast-tools.example.org`.

Render автоматически выпускает TLS-сертификат, поэтому адрес работает по HTTPS.

## Приватность

Текущая версия:

- не содержит базы данных;
- не сохраняет введенные клинические параметры;
- не просит ФИО, дату рождения или номер медицинской карты;
- выполняет расчеты в оперативной памяти;
- запрещает кэширование API-ответов браузером и промежуточными прокси.

Не следует вводить ФИО и другие прямые идентификаторы пациентов в любые
свободные поля, если такие поля будут добавлены позднее.

## Обновления

Если Render подключен к GitHub с Auto-Deploy, то после каждого обновления
ветки `main` он автоматически пересобирает приложение. Старая работающая
версия остается доступной до успешного запуска новой.
